# AWS Virtual Organization Onboarding Example

This example demonstrates how to use the
[terraform-aws-onboarding](https://github.com/upwindsecurity/terraform-aws-onboarding)
module to onboard AWS accounts into an Upwind **virtual organization**: a set
of accounts grouped by Upwind rather than discovered through AWS
Organizations.

Instead of an Organization discovery role in the management account, each
account onboards itself. Applying the module to an account with
`is_virtual_organization = true` creates:

- **Account Service role**: tagged so Upwind can discover the CloudScanner
  roles and the orchestrator account.
- **Credentials secret**: when the client ID and secret are passed as values.
  If you pass `upwind_cloudscanner_auth_secret_arn` instead, the existing
  secret is used.
- **Single account onboarding Lambda**: plus its execution role and log group.
  Terraform invokes it once, on create, and it registers the account with
  Upwind (`upwind_cloud_organization_id`) in the region selected by
  `deployment_region`.

The orchestrator account (`orchestrator_account_id`) additionally receives the
CloudScanner roles, as in a regular organization onboarding.

## Example

See [`main.tf`](./main.tf) in this directory. The key inputs are:

| Input | Description |
| --- | --- |
| `is_virtual_organization` | Set to `true` to enable virtual organization mode. |
| `upwind_cloud_organization_id` | The Cloud Organization ID generated by Upwind. Required when the onboarding Lambda is enabled. |
| `deployment_region` | Upwind SaaS region: `us` (default), `eu`, `ap` or `me`. |
| `upwind_cloudscanner_auth_client_id` / `upwind_cloudscanner_auth_secret_value` | Client credentials, stored in a new secret. |
| `upwind_cloudscanner_auth_secret_arn` | Alternatively, an existing secret holding the credentials. Mutually exclusive with the values above. |
| `upwind_single_account_onboarding_lambda_enabled` | Set to `false` to skip the onboarding Lambda. Defaults to `true`. |
| `single_account_onboarding_role_permissions_boundary` | Optional permissions boundary for the Lambda execution role. |

## Usage

Replace the placeholder values in `main.tf` with the values provided by Upwind
(Cloud Organization ID, external ID and client credentials) and your own
account IDs, then run in each account to onboard:

```shell
terraform init
terraform plan
terraform apply
```

The account appears in the Upwind console once the onboarding Lambda has run
successfully. Its logs are written to the
`/aws/lambda/upwind-single-account-onboarding-<suffix>` CloudWatch log group.
